# «Матрёшка» — основной сайт магазина

Основной адрес нового магазина: https://matreshka-v2.vercel.app/  

Новый сайт представляется посетителям как основной магазин «Матрёшка»: без тестовой плашки, со своим каноническим адресом и разрешённой индексацией. Прежний сайт и его Turso-база остаются неизменными. До завершения проверки размещения персональных данных покупателям доступен каталог, но не приём онлайн-заказов.

Старый сайт (без изменений): https://matreshkachita.vercel.app/  
Ветка исходного кода: matreshka-v2.

## Что уже сделано

- Скопированы 43 реальных товара и 43 фотографии в независимое Vercel Blob-хранилище, без записи в старую базу Turso.
- Новый каталог без Base64 в JSON; страницы по 24 товара, фильтры, поиск, карточки товаров, мобильная версия.
- Новая независимая архитектура PostgreSQL: товары, покупатели, корзина в браузере, заказы, остатки, обращения, отзывы.
- Заказы создаются транзакционно; последние остатки нельзя продать дважды. Есть защита от повторного оформления.
- Админ-панель: товары (поиск и пагинация по 50), загрузка фото, изменение цен и остатков, заказы и статусы оплаты, отзывы и обращения.
- Регистрация и вход через HTTP-only cookie, ограничение попыток входа, отдельная авторизация администратора.
- Оформление заявок с оплатой по согласованию с магазином. Онлайн-эквайринг не подключён.

## Текущий статус и ограничения

На опубликованном домене пока включён режим каталога без приёма заказов, поскольку отдельная облачная PostgreSQL-база не подключена. Код магазина и тесты готовы, но живые заказы не должны включаться до следующих шагов.

## Что нужно владельцу для запуска

1. Создать НОВУЮ PostgreSQL-базу для matreshka-v2 (не копировать переменные Turso со старого chita). Для покупателей из России перед выбором провайдера проверить требования к локализации персональных данных.
2. В Vercel открыть проект matreshka-v2 → Settings → Environment Variables и задать DATABASE_URL для этой новой базы. Существующий BLOB_READ_WRITE_TOKEN относится к отдельному хранилищу фотографий V2.
3. Установить новый JWT_SECRET (случайный секрет минимум 32 символа) и НОВЫЙ ADMIN_PASSWORD (не менее 12 символов). Старый короткий пароль 7316 не использовать.
4. Указать реальные реквизиты продавца: SELLER_LEGAL_NAME, SELLER_LEGAL_ADDRESS, SELLER_CONTACT и SELLER_INN (или SELLER_OGRN). Не использовать данные из автоматических тестов.
5. Утвердить политику обработки данных, условия продажи, возвратов, оплаты и доставки. Провести проверку локализации хранения; только затем задать DATA_LOCALIZATION_REVIEWED=1.
6. Проверить живую админ-панель и сделать контрольный тестовый заказ. Только после этого задать SHOP_OPEN=1 и выполнить повторный деплой.

Примечание: SHOP_OPEN не активирует приём заказов, если отсутствуют безопасные секреты, реквизиты продавца или флаг проверки локализации данных.

## Маршруты API

- GET /api/config — состояние магазина.
- GET /api/products?limit=24&page=1 — каталог, поиск и фильтры.
- GET /api/products/:id — информация о товаре.
- POST /api/auth/register, /api/auth/login, /api/auth/logout — аккаунты.
- GET /api/auth/me, /api/auth/orders — кабинет и заказы пользователя.
- POST /api/admin/login — вход администратора.
- GET /api/admin/products?limit=50&page=1 — управление каталогом.
- POST/PUT/DELETE /api/admin/products — добавление, изменение и снятие с продажи.
- POST /api/orders — создание заказа (только после включения SHOP_OPEN).
- GET /api/admin/orders, PUT /api/admin/orders/:id/status — модерация заказов.
- PUT /api/admin/orders/:id/payment — статус оплаты.
- GET/PUT /api/admin/reviews — проверка отзывов.
- GET /api/admin/requests — обращения покупателей.

## Тесты

Обычные smoke-тесты каталога:

    npm install
    npm test

Для полной интеграционной проверки потребуется отдельная ПУСТАЯ тестовая PostgreSQL-база. Указывать боевую базу в TEST_DATABASE_URL запрещено:

    TEST_DATABASE_URL='postgresql://.../matreshka_test' npm test

Проверены: 500 синтетических товаров, поиск/пагинация, регистрация, админ-вход, добавление товаров, заказы, отмены, конкурентное списание остатков, отсутствие дублей, отзывы и обращения.

## Защита входа в админ-панель

- Пароль администратора задаётся исключительно переменной `ADMIN_PASSWORD` в Vercel. Не хранить пароль в исходном коде.
- После 3 неверных попыток вход с того же IP блокируется на **1 минуту**.
- Каждые следующие 3 неверные попытки после истечения блокировки повышают длительность: **3, 9, 27, 81, 243 минут и далее** (максимальная длительность одной блокировки — 30 суток, во избежание вечной потери доступа).
- Пока действует блокировка, вход невозможен даже с правильным паролем; сервер отдаёт HTTP 429 и заголовок `Retry-After`.
- После успешной авторизации счётчик полностью сбрасывается. Блокировки хранятся в PostgreSQL (`shop_admin_attempts`) и не исчезают после обновления страницы или перезапуска сервера.
- В режиме только каталога **без PostgreSQL** доступ к административным маршрутам безопасно закрыт: надёжно поддерживать постоянный счётчик ошибок без транзакционной базы нельзя.
- После смены переменной `ADMIN_PASSWORD` нужен новый деплой сайта. Новый пароль автоматически делает ранее выданные административные cookie недействительными.

## Корзина, лайки и профили

- Любой посетитель может добавить товар в корзину с главной страницы, из каталога или карточки товара.
- Количество товара нельзя увеличить сверх доступного остатка; корзина сохраняется между открытиями сайта в `localStorage` браузера.
- Кнопка ♥ сохраняет выбранные товары в избранном без регистрации. Профиль открывается нажатием на ♥ в верхнем меню и содержит вкладки **Понравившиеся** и **Моя корзина**.
- Избранное отображается через постраничный каталог (в отличие от старого обработчика, ожидавшего целый массив) и сохраняется после обновления страницы.
- Серверная регистрация и вход по телефону уже реализованы в `shop-auth.js`, с защитой паролей, авторизацией через HttpOnly cookie, объединением избранного с аккаунтом и защитой от перебора.
- **Серверный вход покупателей пока выключен**: база Supabase расположена в Швеции, а применимые требования к хранению персональных данных российских покупателей ещё не реализованы. Пока пользователь видит честное объяснение вместо формы сбора телефона. Для полноценной синхронизации между устройствами нужно законно разместить данные аккаунтов в РФ.
- **Оформление интернет-заказов выключено**: можно собрать корзину и связаться с магазином, но сайт не принимает заявку или платёж. Корзина и избранное хранятся только на текущем устройстве до полноценной регистрации.

## Безопасность и особенности

- Приём заказов на тестовом URL закрыт до завершения настройки. Старый сайт и база Turso не изменялись.
- Пароли не хранить в GitHub, переписке и интерфейсе браузера; их нужно задавать только в защищённых переменных Vercel.
- Копия публичных товаров V2 не включает аккаунты и историю заказов старой версии.
- Настоящая онлайн-оплата, автоматическая отправка чеков, SMS/email-уведомления и интеграция тарифов доставки требуют отдельных договоров и подключений.
- При изменениях правового статуса магазина и условий продаж обновить юридические страницы и реквизиты.
