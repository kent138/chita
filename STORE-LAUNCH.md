# Матрёшка 2.1 — запуск полноценного интернет-магазина

**Сайт:** https://matreshka-v2.vercel.app/  
**GitHub:** kent138/chita, отдельная ветка `matreshka-v2`  
**Vercel:** отдельный проект `matreshka-v2`. Старый `chita` / `master` не изменяются.

## Уже реализовано и протестировано

- Быстрый каталог: по 24 товара, поиск на русском, фильтры по материалу, цене и наличию.
- 43 настоящих товара с изображениями уже сохранены в собственном Blob-хранилище V2.
- Отдельная реляционная база PostgreSQL. При первом подключении автоматически создаёт таблицы и переносит 43 товара из Blob, сохраняя ID, фотографии, цены и остатки. Не подключается к старой Turso.
- Админ-панель: вход с паролем, поиск, добавление/изменение/снятие товара с продажи, загрузка изображений, управление статусами заказов, модерирование отзывов, обращения.
- Покупатель: регистрация, вход с HttpOnly cookie, личный кабинет, адреса, избранное, корзина, оформление заказа и история.
- Заказ: сервер сам рассчитывает цены, проверяет и резервирует остатки в PostgreSQL-транзакции. Повторная отправка не создаёт дубликат. Отмена возвращает остатки, повторная отмена безопасна. История заказов не удаляется.
- Персональные данные и заказы не записываются в Blob и не затрагивают старый магазин.
- Платёжная система **не подключена**: в checkout доступны только «При получении» и «Согласовать с магазином». Стоимость доставки согласуется отдельно.
- Данные продавца, пароль и локализация проверяются до разрешения настоящих заказов.

## Что подключить перед приёмом заказов

Создайте **НОВУЮ, отдельную базу PostgreSQL** с допустимым для вашей деятельности размещением персональных данных. Важно: для обработки персональных данных граждан России при сборе через интернет необходимо проверить требования локализации по ст.18 ч.5 Федерального закона №152-ФЗ и остальные требования применимого законодательства. Не копируйте старые секреты Turso.

В Vercel > Project `matreshka-v2` > Settings > Environment Variables:

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Закрытое подключение к **новой** PostgreSQL-базе (TLS) |
| `BLOB_READ_WRITE_TOKEN` | Уже подключено Vercel Blob V2, не изменять |
| `JWT_SECRET` | Новый случайный секрет **не менее 32 символов** |
| `ADMIN_PASSWORD` | **Новый** секрет администратора **не менее 12 символов**, не 7316 |
| `SELLER_LEGAL_NAME` | Полное юридическое название продавца / ФИО ИП |
| `SELLER_OGRN` | ОГРН/ОГРНИП (13 или 15 цифр) |
| `SELLER_LEGAL_ADDRESS` | Юридический адрес продавца |
| `SELLER_CONTACT` | Публичный email или телефон продавца |
| `DATA_LOCALIZATION_REVIEWED` | `1` только после проверки условий обработки и хранения данных |
| `SHOP_OPEN` | `0` во время тестирования, `1` только после реальной проверки |

По умолчанию заказ недоступен. При подключении `DATABASE_URL` создаётся реляционная схема с отдельными таблицами shop_users, shop_products, shop_orders, shop_order_items, shop_reviews и другими. Начальное заполнение из 43 товаров происходит однократно, только при пустой таблице товаров. При повторном запуске существующие данные не перезаписываются.

**Важно:** на тестовом сайте ранее применялся короткий пароль 7316. Новый API не принимает административный пароль короче 12 символов, а вход осуществляется через защищённую cookie. Старый пароль следует отдельно сменить и на исходном сайте.

## Прогон проверки перед открытием

1. Проверить `GET /api/config`: databaseReady=true, sellerReady=true. При `SHOP_OPEN=0` acceptingOrders=false.
2. Зайти в админ-панель через меню `⋯`, обновить тестовый товар и проверить, что изменение сохранилось после перезагрузки.
3. Проверить 43 исходных товара, фотографии, фильтры и остатки.
4. В **отдельном тестовом окружении** выполнить тестовый заказ, проверить транзакции и отмену, затем убрать тестовые записи.
5. Утвердить публичную оферту, политику персональных данных, сведения продавца, условия доставки и возврата, порядок выдачи чеков и кассовое решение, если применимо.
6. Настроить ежедневные резервные копии PostgreSQL, мониторинг ошибок и уведомления о заказах.
7. Только затем поставить `DATA_LOCALIZATION_REVIEWED=1` и `SHOP_OPEN=1` и сделать новое развёртывание.

## Тесты разработчика

```bash
npm install
npm test
```

Для интеграционных тестов нужна **отдельная локальная тестовая PostgreSQL** и `TEST_DATABASE_URL`; тесты не должны запускаться на базе покупателей. Они проверяют 500 синтетических товаров, регистрацию, админ-панель, заказ и защиту от одновременной продажи последней единицы, отмену и отзывы.

**Ограничения**: не подключены эквайринг, СБП как автоматическая оплата, расчёт доставки через СДЭК/Почту России, кассовая интеграция и автоматическое оповещение по электронной почте или Telegram. Их нельзя объявлять действующими без реальных провайдеров и проверки.
